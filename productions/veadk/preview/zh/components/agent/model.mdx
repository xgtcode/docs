模型负责理解输入、选择工具并生成回答。智能体默认读取环境变量或 `config.yaml` 中的全局模型配置，也可以通过 `Agent` 参数为不同智能体分别配置模型、端点和凭证

## 为单个智能体指定模型

先完成[安装](/productions/veadk/preview/zh/get-started/installation)，并选择以下一种平台配置。模型需已在对应账号中开通；也可以将名称替换为有权访问的模型或推理接入点

<Tabs>
<Tab title="火山引擎">
```bash  lines
export CLOUD_PROVIDER="volcengine"
export MODEL_AGENT_NAME="doubao-seed-2-1-pro-260628"
export MODEL_AGENT_API_BASE="https://ark.cn-beijing.volces.com/api/v3/"
export MODEL_AGENT_API_KEY="<model-api-key>"
```

</Tab>
<Tab title="BytePlus">
```bash  lines
export CLOUD_PROVIDER="byteplus"
export MODEL_AGENT_NAME="seed-2-0-lite-260228"
export MODEL_AGENT_API_BASE="https://ark.ap-southeast.bytepluses.com/api/v3"
export MODEL_AGENT_API_KEY="<model-api-key>"
```

</Tab>
</Tabs>

在同一终端运行以下 `main.py`：

```python main.py lines
import asyncio
import os
from veadk import Agent, Runner

agent = Agent(
    name="assistant",
    model_name=os.environ["MODEL_AGENT_NAME"],
    model_provider="openai",
    model_api_base=os.environ["MODEL_AGENT_API_BASE"],
    model_api_key=os.environ["MODEL_AGENT_API_KEY"],
)

async def main():
    print(await Runner(agent=agent).run(
        messages="Explain what an AI agent does in one paragraph.",
        session_id="model-demo",
    ))

if __name__ == "__main__":
    asyncio.run(main())
```

执行 `python main.py` 后会输出模型回答。若所有智能体共用上述配置，可以直接使用 `Agent(name="assistant")`

### 模型参数与全局配置

显式构造参数覆盖对应的全局配置；未传入的字段沿用全局值。`config.yaml` 从当前目录向上查找，已有环境变量优先于配置文件中的同名设置。配置文件写法见[快速开始](/productions/veadk/preview/zh/get-started/quickstart)

| 参数 | 类型 | 默认值 | 对应环境变量或说明 |
| :--- | :--- | :--- | :--- |
| `model_name` | `str \| list[str]` | 平台默认模型 | `MODEL_AGENT_NAME`；列表用于模型回退 |
| `model_provider` | `str` | `"openai"` | `MODEL_AGENT_PROVIDER`；LiteLLM 提供商标识，兼容 OpenAI 协议的方舟端点使用 `openai` |
| `model_api_base` | `str` | 平台默认端点 | `MODEL_AGENT_API_BASE` |
| `model_api_key` | `str` | `""`，初始化时解析 | `MODEL_AGENT_API_KEY` |
| `model_api_key_name` | `str` | `""` | `MODEL_AGENT_API_KEY_NAME`；按名称查询方舟 API Key |
| `model_fallbacks` | `list[str \| ModelFallbackEndpoint]` | `[]` | 追加的回退模型或端点，也接受匹配字段的字典 |
| `model_extra_config` | `dict` | `{}` | 模型请求的额外配置；可用字段取决于所用接口 |
| `enable_responses` | `bool` | `False` | 启用火山方舟 Responses API |
| `enable_responses_cache` | `bool` | `True` | Responses 模式下的缓存开关 |
| `query_routing` | `bool \| dict \| QueryRoutingConfig` | `None` | 查询分级与模型路由。`None` 自动读取 `config.yaml` 的 `query_routing` 配置，`False` 显式关闭。详见[查询分级与模型路由](#查询分级与模型路由)。 |

未覆盖全局默认值时，火山引擎使用 `doubao-seed-2-1-pro-260628` 和 `https://ark.cn-beijing.volces.com/api/v3/`；设置 `CLOUD_PROVIDER=byteplus` 后使用 `seed-2-0-lite-260228` 和 `https://ark.ap-southeast.bytepluses.com/api/v3`。切换平台前请同时检查原有 `MODEL_AGENT_*` 环境变量，避免继续使用另一平台的配置

### 按名称解析 API Key

API Key 的解析顺序为：非空 `model_api_key`、`MODEL_AGENT_API_KEY`、`model_api_key_name` 或 `MODEL_AGENT_API_KEY_NAME` 指定的名称，最后使用账号中默认查询到的 Key

```bash lines
export MODEL_AGENT_API_KEY_NAME="production-key"
```

按名称查询需要有权读取方舟 API Key 的账号凭证；该名称不是密钥值。已有 Key 值时不会再按名称查询。该能力从 VeADK 1.0.2 开始提供

### 限流重试

默认 `adk` 运行时、未启用 Responses 且未传入自定义 `model` 时，VeADK 会对尚未产生任何模型响应的 HTTP 429 错误重试一次。延迟取有效的 `Retry-After` 数值，上限为 2 秒；缺失或无效时使用 0.5 秒。已开始输出的请求不会由这层重试重新执行

## 配置回退模型

在前面的示例中额外设置 `BACKUP_MODEL_NAME`，并将 `agent` 定义替换为：

```python  lines
agent = Agent(
    name="assistant",
    model_name=[os.environ["MODEL_AGENT_NAME"], os.environ["BACKUP_MODEL_NAME"]],
)
```

列表第一项为主模型，其余按顺序作为回退候选，共用提供商、端点和凭证。也可以使用 `model_fallbacks=["备用模型名称"]` 追加同提供商模型；若两处均有配置，先尝试 `model_name` 列表中的候选，再尝试 `model_fallbacks`

默认模型接口与 Responses API 均可配置同提供商名称回退，候选模型必须支持同一请求所用的工具、多模态或输出格式。回退用于处理请求失败，不会因回答质量不佳自动切换模型

## 配置跨提供商回退模型

备用模型使用不同提供商、端点或凭证时，使用 `ModelFallbackEndpoint`。运行前除主模型配置外，还需设置 `BACKUP_MODEL_NAME`、`BACKUP_MODEL_PROVIDER`、`BACKUP_MODEL_API_BASE` 和 `BACKUP_MODEL_API_KEY` 为备用服务的实际配置

```python fallback.py lines
import asyncio
import os
from veadk import Agent, ModelFallbackEndpoint, Runner

agent = Agent(
    name="assistant",
    model_fallbacks=[
        ModelFallbackEndpoint(
            model_name=os.environ["BACKUP_MODEL_NAME"],
            model_provider=os.environ["BACKUP_MODEL_PROVIDER"],
            model_api_base=os.environ["BACKUP_MODEL_API_BASE"],
            model_api_key_env="BACKUP_MODEL_API_KEY",
        ),
    ],
)

async def main():
    print(await Runner(agent=agent).run(
        messages="Explain model fallback briefly.", session_id="fallback-demo"
    ))

if __name__ == "__main__":
    asyncio.run(main())
```

### `ModelFallbackEndpoint` 参数

| 参数 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `model_name` | `str` | 必填 | 模型名称；不带前缀且未指定提供商时使用主模型提供商 |
| `model_provider` | `str \| None` | `None` | 备用提供商；使用不同提供商时不会沿用主模型端点和凭证 |
| `model_api_base` | `str \| None` | `None` | 备用端点；跨提供商未设置时由 LiteLLM 使用提供商默认地址，并非所有提供商都有默认地址 |
| `model_api_key` | `str \| None` | `None` | 备用 Key 值，优先于 `model_api_key_env` |
| `model_api_key_env` | `str \| None` | `None` | 保存备用 Key 的环境变量名称，创建智能体时读取；缺失时由 LiteLLM 尝试提供商默认凭证 |
| `model_extra_config` | `dict` | `{}` | 备用请求配置；显式提供的 `extra_headers`、`extra_body` 字典与主模型对应字典按键合并，备用值覆盖同名键，不递归合并嵌套对象 |

可以使用字典代替对象，支持 `model`、`provider`、`api_base` 或 `base_url`、`api_key`、`api_key_env`、`extra_config` 别名。跨提供商时建议明确填写 `model_provider`、端点和凭证，避免继承不适用的配置

### 回退限制

- `enable_responses=True` 只接受字符串形式的同提供商回退；端点对象或字典会导致初始化失败
- `codex` 和 `piagent` 运行时忽略回退链；需要该能力时使用 `adk`，参见[运行时](/productions/veadk/preview/zh/components/agent/runtime#切换执行后端)
- 在默认运行时显式传入自定义 `model` 对象时，`model_fallbacks` 不生效，应在该对象上配置回退

## 查询分级与模型路由

SystemOne 在每个用户 turn 开始时，根据有效历史、指令、工具声明及候选模型能力选择一次模型。工具循环、嵌套 AgentTool 和子 Agent 转交全程保持该选择；下一个用户 turn 重新判断。该能力默认关闭，只有显式配置才生效；不配置时保留原有执行行为。

<Warning>
查询分级与模型路由仅支持 `adk` 运行时。开启路由时必须移除 `model_name` 列表回退和 `model_fallbacks`，二者不能同时使用。
</Warning>

### 配置方式

在项目根目录的 `config.yaml` 中新增配置块：

```yaml title="config.yaml"
decision:
  model: doubao-seed-2-1-lite-260915

query_routing:
  simple_models:
    - doubao-seed-2-1-lite-260915
  # strong_model: kimi-k3-1-pro-261024  # 可选；默认使用 Agent 的 model_name
  mode: shadow  # 先观察；设为 enforce 才实际执行路由
  decision_timeout: 2.0
  questions:
    - question: 回答是否需要最新的实时信息？
      threshold: 0.2
```

Agent 启动时会自动发现当前工作目录及上级目录中的 `config.yaml`，无需额外代码：

```python title="agent.py"
agent = Agent(model_name="kimi-k3-1-pro-261024")
```

也可以直接传入字典：`Agent(query_routing={...})`；显式关闭则传 `query_routing=False`。

### 参数

| 字段 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `simple_models` | `list[str \| dict]` | 必填 | 低成本模型列表，至少一个。按列出顺序选择第一个满足当前请求能力要求的模型。字符串等价于只声明 `name` 的字典。 |
| `strong_model` | `str` | Agent 的 `model_name` | 强模型名称。与 Agent 的主模型不同时，用同一套连接信息单独构建。 |
| `mode` | `"enforce" \| "shadow"` | `"shadow"` | `shadow` 只记录分级结果，所有请求仍走强模型，便于观察效果后再切换。 |
| `decision_timeout` | `float` | `2.0` | 单次分级超时（秒），范围 `(0, 30]`。超时按强模型处理。 |
| `builtin_thresholds` | `dict[str, float]` | `{}` | 可覆盖内置问题阈值，范围 `[0, 1]`；正式执行前应使用代表性查询校准。 |
| `questions` | `list[str \| dict]` | `[]` | 追加到四个内置问题之后的自定义问题。字符串等价于 `{question: ...}`。 |

### 公共决策连接

根级 `decision` 由查询路由和内容安全共用，配置它不会启用任何功能。代码中通过 `Agent(decision=DecisionConfig(...))` 显式传入不可变连接配置；各功能独立创建客户端、管理问题。连接只在公共位置配置，不放在功能内部。

| 配置项 | 必填 | 默认值 / 规则 |
| :--- | :--- | :--- |
| `decision.api_url` | 否 | 从 Agent 的方舟地址推导 `/api/v1/systemone`；使用自定义网关时必填。 |
| `decision.api_key` | 否 | 复用 Agent 的方舟密钥；非方舟决策地址必须显式填写。 |
| `decision.model` | 否 | `doubao-seed-2-1-lite-260915`，用于 SystemOne 决策的模型。 |

`DECISION_API_URL`、`DECISION_API_KEY`、`DECISION_MODEL` 可覆盖 YAML。覆盖已配置的目标地址时，必须同时提供对应的 `DECISION_API_KEY`。显式构造 `DecisionConfig` 不读取文件或环境变量。问题、阈值及 `decision_timeout` 归各功能管理；修改路由规则不会修改内容安全规则。

```python
from veadk import Agent
from veadk.decision import DecisionConfig

agent = Agent(
    name="router",
    decision=DecisionConfig(model="doubao-seed-2-1-lite-260915"),
    query_routing={"simple_models": ["doubao-seed-2-1-lite-260915"]},
)
```

### 候选模型能力声明

每个 `simple_models` 条目可声明能力；未声明的能力一律视为不支持：

| 能力字段 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `name` | `str` | 必填 | 模型名称，也可写成 `model` 或 `model_name`。 |
| `provider` | `str` | Agent provider | 无前缀名称使用的 LiteLLM provider。 |
| `api` | `str` | Agent 协议 | `chat_completions` 或 `responses`（方舟 Responses 适配器）。 |
| `api_base` | `str` | Agent endpoint | 独立 endpoint；不同 endpoint 必须显式配置凭据。 |
| `api_key_env` / `api_key` | `str` | Agent 凭据 | 环境变量名或密钥值，二者互斥；推荐 `api_key_env`。 |
| `extra_config` | `dict` | `{}` | Provider 选项，不得覆盖路由、历史及连接字段。独立 endpoint 不继承 Agent 的 provider 选项。 |
| `supports_tools` | `bool` | `False` | 是否支持工具调用。 |
| `capability_description` | `str \| None` | `None` | 可选，1–2000 字符。向 SystemOne 说明候选模型经验证的适用任务、限制及工具依赖；不是提示词覆盖，不替代能力标记或阈值，也不自动保证质量。不得包含凭据。 |
| `supports_media` | `bool` | `False` | 是否支持图片、音频、视频或文件输入。 |
| `supports_structured_output` | `bool` | `False` | 是否支持结构化输出。 |
| `max_context_chars` | `int` | `32000` | 包含指令、工具、schema 和历史的字符预算；媒体按固定成本估算，不等同于 tokenizer 精确的上下文窗口保证。 |

### 内置问题与阈值

内部控制问题固定为 `noul` 类型，内置四个：

| 问题 ID | 默认阈值 | 判断内容 |
| :--- | :--- | :--- |
| `is_complex` | `0.5` | 推理、规划、代码或数学是否超出候选模型已声明的能力。 |
| `needs_tools` | `0.5` | 工具编排或恢复是否超出候选模型已声明的能力；已支持的简单工具调用不会因此自动升级。 |
| `needs_long_context` | `0.5` | 当前任务是否需要跨较长历史或多份材料做全局分析；从少量最近消息提取已给出的事实不属于长上下文分析。 |
| `is_high_stakes` | `0.05` | 当前任务是否要求医疗、法律、金融、安全等高风险结论或不可撤销操作；历史出现高风险主题不会自动将当前的普通事实提取升级，但继续追问相关建议仍属于高风险。 |

默认阈值为：复杂推理、工具编排、长上下文 `0.5`，高风险 `0.05`。`builtin_thresholds` 中显式填写的值优先；自定义问题省略阈值时仍使用 `0.15`。阈值是 SystemOne 问题概率的上限，不是任务错误率。未启用路由时不生效，`shadow` 模式仍由强模型执行。

自定义问题只需提供 `question` 与 `threshold`，ID 自动生成为 `custom_1`、`custom_2`……；内置 ID 保留，不能覆盖。所有问题都返回 `0` 到 `1` 的概率，**只有全部不超过各自阈值时才走简单模型**；任一问题超过阈值、返回值缺失或非法、Decision 超时或报错时，都走强模型。决策输入不完整、媒体无法表示或动态工具声明不可用时也选择强模型，不会静默截断有效历史以促成降级。选择确定后，provider 失败直接传播，不切换模型；超时、连接错误、429 或 5xx 等瞬时失败会让该简单模型在 60 秒冷却期内从后续 turn 的候选中排除，这些 turn 因此走强模型，冷却结束后再重新尝试。其余 4xx 属于单次请求问题，不会触发冷却。后续请求超出候选能力时显式报错。

### enforce 模式下的工具参数校验

在 enforce 模式下，工具执行前会按工具声明的 schema 校验参数。明确声明为整数的十进制整数字符串可无损转换；小数、布尔值及歧义格式不会被强制转成整数。不合法的参数返回不包含原始参数值的结构化错误，由本 turn 已选择的模型纠正，整个根 turn（含嵌套 Agent）最多返回两次纠正反馈，随后明确报错。已经执行的工具不会因此被自动重试。工具没有参数 schema 时保持原有行为；schema 无法构造或包含非本地引用（如 `$ref`/`$dynamicRef`）等校验器自身错误会记录日志并跳过本次校验，不阻断工具调用。未启用路由、shadow 模式以及本 turn 选择强模型时，均保留原有工具参数行为。

### Responses 续链与路由

只有目标、endpoint、身份、请求配置及有效历史一致时才复用 Responses 续链。切换模型（包括 A → B → A）会使用完整业务历史重建；ID 过期时在同一模型上携带完整历史重试。不同目标间不重放 provider 专属的推理内容及签名。`enable_responses_cache=False` 始终发送完整历史。服务端缓存仍需对应模型的缓存服务权限；Responses 续接也可使用 `store=True` 与 `extra_body={"caching": {"type": "disabled"}}`。

### 嵌套 Agent 与生命周期

嵌套 AgentTool 保持独立 session，并继承同一个根决策。原生 ADK LlmAgent 及标准子 Agent 工作流通过独立副本适配；自定义原生 LlmAgent 子类需显式实现 turn 绑定。恢复执行使用 session 中按路由 Agent 命名空间持久化的决策；同一 invocation 内通过原生转交到达的独立配置路由 Agent 各自记录决策，互不覆盖，同一路由 Agent 的配置变化仍显式报错。决策 HTTP 客户端随 Agent/Runner 生命周期关闭，不在每个 continuation 后重建。双向 Live 执行及外部 runtime 不在此 ADK 文本 turn 契约内。同一 session 的并发执行仍需应用侧串行化；跨进程同时分级不提供分布式锁。

模型事件提供 `veadk_query_routing` 元数据，包含根 turn ID、路由、模型及目标摘要。决策事件还包含原因、耗时及服务上报的输入 token 数，不包含凭据或原始 query。

### 完整示例

```python title="agent.py"
agent = Agent(

    query_routing={
        "mode": "enforce",
        "simple_models": [{
            "name": "small-model",
            "provider": "openai",
            "api": "chat_completions",
            "api_base": "https://models.example.com/v1",
            "api_key_env": "SMALL_MODEL_API_KEY",
            "supports_tools": True,
        }],
    },
)
```

## Responses API

Responses API 提供多轮上下文衔接、多模态输入和结构化输出。使用前确认目标端点与模型支持火山方舟 Responses 协议；普通的 OpenAI 兼容端点不代表支持本节全部能力

### 启用

需要 `google-adk>=1.34.0`。在模型已经配置好的基础上设置 `Agent(enable_responses=True)`；默认关闭该功能。BytePlus 应使用该账号可用且明确支持对应能力的模型与端点，不能仅通过切换开关获得支持

### 多模态理解

`FileData.file_uri` 支持以下来源，`mime_type` 应与文件内容一致：

| 来源 | 写法 | 使用条件 |
| :--- | :--- | :--- |
| 本地文件 | `file:///绝对路径/example.png` | 运行进程可读取文件；VeADK 通过 Files API 上传 |
| 已上传文件 | `file_id://文件标识` | 文件属于可访问的 Files API 资源 |
| 网络地址 | `https://...` | 模型服务可访问该地址 |

<Note>
本地文件会发送到模型服务。运行前确认文件内容适合上传，并检查服务支持的格式与大小限制
</Note>

将一张 PNG 图片保存为当前目录的 `example.png`，然后运行 `python image_reader.py`：

```python image_reader.py lines
import asyncio
from pathlib import Path
from google.genai import types
from veadk import Agent, Runner

async def main():
    image_path = Path("example.png").resolve(strict=True)
    agent = Agent(name="image_reader", enable_responses=True)
    runner = Runner(agent=agent, app_name="image_demo", user_id="demo-user")
    await runner.session_service.create_session(
        app_name="image_demo", user_id="demo-user", session_id="image-session"
    )
    message = types.Content(role="user", parts=[
        types.Part(text="Describe this image."),
        types.Part(file_data=types.FileData(
            file_uri=image_path.as_uri(), mime_type="image/png"
        )),
    ])
    async for event in runner.run_async(
        user_id="demo-user", session_id="image-session", new_message=message
    ):
        if event.is_final_response() and event.content:
            print("".join(part.text or "" for part in event.content.parts or []))

if __name__ == "__main__":
    asyncio.run(main())
```

视频元数据应设置在 `types.Part` 上，与 `file_data` 并列。以下片段可替换图片 Part，抽帧频率的可用范围以模型服务为准：

```python  lines
video_part = types.Part(
    file_data=types.FileData(
        file_uri=Path("example.mp4").resolve(strict=True).as_uri(),
        mime_type="video/mp4",
    ),
    video_metadata=types.VideoMetadata(fps=1),
)
```

### 配置方舟上下文管理

对于支持 `context_management` 的模型，可通过 `model_extra_config` 提供配置。以下片段请求清理较早的思维内容，仅保留最近一个思维轮次：

```python  lines
agent = Agent(
    enable_responses=True,
    model_extra_config={
        "context_management": {
            "edits": [{
                "type": "clear_thinking",
                "keep": {"type": "thinking_turns", "value": 1},
            }],
        },
    },
)
```

### 上下文缓存

Responses 模式默认启用缓存。缓存命中取决于服务及请求内容，不保证每次都降低用量。可设置 `enable_responses_cache=False` 关闭

返回事件的 `usage_metadata.cached_content_token_count` 表示缓存命中的 token 数，`prompt_token_count` 表示输入 token 总数；后者大于零时才可计算两者之比。使用 `Runner.run_async` 读取事件以检查用量

配置 `output_schema` 时，VeADK 会移除与结构化输出冲突的缓存设置，示例见[结构化输出](/productions/veadk/preview/zh/components/agent/structured-output)
