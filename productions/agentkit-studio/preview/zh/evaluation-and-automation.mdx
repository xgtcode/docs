调试对话只能说明智能体如何回答一个问题。要比较修改提示词、模型或工具前后的效果，可以用同一组样本做评测。要验证并发调用时的响应情况，则使用压力测试，而不是回答质量评分。

## 用样本验证改动

1. 保存要测试的智能体，在**评测**中准备评测集。也可以使用创建智能体时自动生成的默认评测集，先逐条核对样本是否符合业务要求。若使用模型评分，请先在 Studio 设置中配置可用的评测模型。
2. 选择输入输出评测，指定智能体、评测集和评测指标。例如，对会议待办助手，样本输入可以是一段没有截止时间的会议记录，预期结果应要求保留「未指定」，而不是猜测日期。
3. 启动评测，等待任务完成。打开报告，除了查看通过率，还应检查失败样本的实际回答、评分理由和证据。修改智能体后用相同样本和指标重测。

## 评估执行步骤

输入输出评测只能检查最终回答。如果需要判断智能体是否通过合适的步骤得出答案，请使用轨迹评测，选择含执行记录的评测集。预览版支持在轨迹基准中用文字描述预期步骤，例如「先查询产品手册，再根据查到的条款回答」。评审模型会将实际执行过程与这段描述对照评分；不填写预期轨迹时，则根据用户请求判断实际步骤是否合理。

## 检查并发性能

<Warning>
压力测试会真实调用目标智能体及其模型和工具。请先使用测试资源、较小并发数和不会修改线上数据的提示词。
</Warning>

在评测的**压力测试**中选择目标，填写提示词、并发用户数、每秒新增用户数、运行时长和停止等待时间。任务结束后，可下载 Locust 的 HTML 或 CSV 报告查看响应时间和失败请求。任务已完成表示测试结束，不代表每个请求都成功。

## 安排重复任务

需要每天让同一个智能体生成简报时，先在 Studio 中配置定时调度服务。进入**自动化 → 定时任务**，选择已保存的智能体、填写任务指令、设置运行时间并核对时区。保存后查看执行历史，按单次运行的状态和结果判断是否成功；任务已入队不代表已经执行完成。

对于由代码变更触发的工作，**自动化**还提供 GitHub PR 评审。先在代码集成设置中准备共享 Runner，并授权目标仓库；再创建评审绑定。配置完成后，非草稿 PR 的新建或更新可以触发评审，结果出现在对应 PR 中。绑定前请确认允许该集成读取仓库并发表评论。
