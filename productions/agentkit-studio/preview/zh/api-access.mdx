已保存的通用智能体可以在 Studio 之外使用。业务后端需要延续多轮对话时，可以调用托管智能体的文本接口；已有协议客户端可以使用兼容接口。网页访客和飞书用户使用各自的渠道入口，不需要持有智能体 API Key。

## 区分身份与存储

| 对象 | 作用与边界 |
| --- | --- |
| 部署者与运行角色 | 部署者授权 `aks` 准备云资源。Studio 上线后使用绑定的 IAM 角色访问云服务，不使用部署者的浏览器会话。遇到云服务拒绝访问时，检查运行角色对目标项目和地域的权限。 |
| 登录用户与调用方 | 登录身份决定用户可见的智能体和可执行的操作。智能体 API Key 只用于调用指定智能体；签发者失去访问权限后，原 Key 也不能继续使用。 |
| 智能体配置与会话 | 配置保存模型、指令和资源引用；会话由运行时管理。删除智能体配置不会删除共享运行时，也不能替代按会话存储策略清理历史数据。 |
| 评测数据 | 评测集和运行结果独立保存，按云服务商、项目和地域区分。修改评测集影响后续运行，不会改写历史报告。 |

## 从后端发送一条消息

在智能体详情的**集成能力 → API 访问**中，选择托管智能体 API，复制调用地址和 API Key。该地址以 `/api/v1/harness_agent/{agent_id}/invoke` 结尾。请使用界面提供的完整地址，不要拼接共享运行时的地址。

<Warning>
API Key 代表签发者对该智能体的调用权限。请通过后端密钥管理工具注入，不要把它放进网页 JavaScript、聊天记录或代码仓库。
</Warning>

在装有 `curl` 的后端终端中，将 `STUDIO_INVOKE_URL` 设为复制的 HTTPS 地址，并通过安全方式设置 `STUDIO_AGENT_KEY`。以下示例发起一次文本调用：

```bash
curl --fail-with-body -sS -X POST "$STUDIO_INVOKE_URL" \
  -H "Authorization: Bearer $STUDIO_AGENT_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"e12d3b16-ae91-44be-a324-46da88776774","prompt":"周四前由林悦发送报价单。请提取待办。"}'
```

成功响应的 `data.text` 是回答，`data.session_id` 是会话标识。同一调用身份继续对话时复用该 UUID；为每个新对话生成不同的 UUID，不要让不同用户共用示例值。如果请求被拒绝，检查地址和密钥是否来自同一个智能体，以及签发者现在是否仍有调用权限。浏览器登录 Cookie 不能代替此接口的 API Key。

## 选择其他协议或渠道

| 入口 | 适用场景与边界 |
| --- | --- |
| Messages | 已有 Anthropic Messages 客户端可发送消息或接收流式回复。请求需带 `anthropic-version: 2023-06-01`；当前不支持精确的 `count_tokens`，该操作返回 HTTP 501。 |
| Responses、Chat Completions | 使用兼容 OpenAI 协议的客户端，通过智能体页面提供的相应地址发送请求。客户端负责传递历史消息和客户端工具结果，不会自动获得 Studio 的服务端工具。 |
| A2A | 使用 Agent Card 发现智能体；支持发送消息、流式消息和按任务 ID 查询状态。 |
| MCP | 在智能体的 MCP 集成中部署服务，使 MCP 客户端通过 `invoke_agent` 工具调用它。部署会创建云服务，请先确认网关权限和费用。 |
| 网页 | 在网页集成中注册网站、配置允许的来源，将生成的嵌入代码放入该网站。访客通过单独的访客会话对话，不要嵌入后端 API Key。 |
| 飞书 | 为托管智能体配置专享网关，在「集成 → 消息渠道」中绑定机器人，再从飞书发送测试消息；文字回复可流式显示。 |

## 飞书私聊

在预览版中，使用已关联飞书身份的账号登录 Studio，可以在「会话」中看到自己与已绑定机器人的私聊，按更新时间与普通会话一起排列。打开后可以刷新查看消息，不能在 Studio 代发回复。其他人的私聊不会出现在列表中。

在飞书私聊里发送 `/new` 可开始新会话，发送 `/rename 周报整理` 可重命名当前会话。需要回到 Studio 查看这段记录时，在飞书中发送 `/studio`；继续对话仍需回到飞书。
